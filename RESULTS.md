### What the test set shows

1. **On accuracy, the falsification loop does not beat plain ReAct with the same tools,** and neither beats the
   fixed pipeline overall. The three are within 0.02 of each other.
2. **Skeptic is wrong with confidence about half as often** (6.9% vs 12.7%, p = 0.017), and its risk-coverage
   curve is much lower. When it says it is at least 70% sure it is right 90% of the time, against 83% for ReAct.
   It pays for this by abstaining more often (18.5% vs 10.1%). The loop turns confident errors into abstentions.
   This metric was defined in the README before the run but was not one of the stated predictions, so treat it as
   a strong secondary finding, not a confirmed hypothesis.
3. **Prediction 2 failed for an instructive reason.** After the v2 analysis, the identifiability *tool* itself
   tests precision, agreement between trips and a physical value. ReAct follows that verdict, so Skeptic's gate
   adds nothing. Putting the judgement into the tool helped every agent. On one window (7 Dec, a single trip)
   Skeptic overruled the tool in all 3 seeds. Its argument was that 76% of the friction signal there comes from
   cased hole and that the trip estimate rests on global weight terms. The argument is defensible, but the key
   says "answer".
4. **Where judgement pays off:** the fixed pipeline cannot abstain (identify 0.14) and misses report-side
   faults in open audits. Both LLM agents score 1.00 and 0.86 on identify.
5. **Open audits remain hard for every system:** fixed 0.50, ReAct 0.39, Skeptic 0.22.

### A flaw found in the test set after the run

On days whose report has no drilling, `check_clock_offset` returned a placeholder correlation of −2.0 and
the verdict "aligned". The oracle accepted that output, so 2 of the 63 tasks are not valid controls:
`test-clock-control-1` and `test-clock-control-3`. Skeptic and its reviewer flagged the impossible value and
abstained. ReAct accepted "aligned" and was scored correct.

The headline above keeps both tasks, as pre-registered. A post-hoc check without them gives all three systems
0.770 accuracy, so the conclusions do not change. The bug is fixed after the run: the check now says
"insufficient data", and the builder skips such days. The development set is not affected.

### A second flaw: cut-off critic replies counted as "accept"

The skeptic critic replies in JSON with a 2,000-token limit. In the test run, 33 of its 188 reviews were cut
off mid-reply and could not be parsed, and the harness counted every unparseable reply as "accept". In 10 of
the 33 the visible text says `"decision": "reject"`, so the critic gate let through 10 answers it meant to
send back. The results above measure the system as it ran, with a weaker critic than designed. Fixed on
2026-11-22, not evaluated: a cut-off reply keeps its visible decision and finished objections, and the
critic is asked for at most 3 short objections.
